## 本次评审的输入在 stdin

stdin 的结构如下（`===` 行是分隔标记）：

```
=== 变更元信息 ===
源分支: <本次 MR 的源分支>
目标分支: <合并目标分支>
Commit: <被评审的提交 SHA>

=== 未直传的变更文件索引（可能没有这一节）===
<每行一个变更文件，行尾 => 后是该文件完整 diff 的本地路径>

=== DIFF ===
<相对合并目标的 unified diff，即本次 MR 的全部改动>
```

## diff 索引

diff 超出阈值时会按优先级截断，被截掉的文件列在「未直传的变更文件索引」里。这一节存在时：

- 每项行尾 `=>` 后面是该文件**完整 diff 的本地文件路径**，请用 read 工具读取，并纳入评审范围；
- 读的是那个 **diff 文件**，不要读仓库里的当前文件——当前文件体现不出本次改动，被删除的文件也已不存在。

评审范围就是 diff 里的改动（含索引指向的部分）。为了判断这些改动是否正确，你可以读取仓库里的任何其它文件作为上下文。

按输出契约给出结果。
